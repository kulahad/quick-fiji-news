# Quick Fiji News

## News fetching and caching

The app prefers a prebuilt static snapshot, then falls back to live scraping if
the snapshot is unavailable.

- `NEXT_PUBLIC_NEWS_SNAPSHOT_URL` (optional): absolute URL to a generated
  `latest.json` snapshot, for example a GitHub Pages artifact. Leave it unset in
  local development to use `/news/latest.json`.
- `/api/news-stream`: live fallback used when the snapshot cannot be fetched or
  is invalid. It streams headlines as sources complete and reports partial
  source failures.
- `/api/news`: fetches all configured sources server-side and returns combined
  headlines without streaming.

The static snapshot is generated by:

```bash
pnpm build:json
```

`pnpm build:static` runs that step before `next build`.

A GitHub Actions workflow regenerates the snapshot every 30 minutes and deploys
it to GitHub Pages rather than committing it into `main`. For this to work,
enable GitHub Pages with the `GitHub Actions` source and configure the Vercel
project with:

```bash
NEXT_PUBLIC_NEWS_SNAPSHOT_URL=https://<user>.github.io/<repo>/news/latest.json
```

The app also uses an in-browser cache (`localStorage`) so previously loaded
headlines can appear immediately while a refresh is in progress. Source status,
partial failures, and the last successful update time are exposed by `useNews()`.

## Local development

```bash
pnpm install
pnpm dev
```

There is no committed `public/news/latest.json`. During local development the app
requests `/news/latest.json`, gets a 404, and falls back to `/api/news-stream`; to
test the static path locally, run `pnpm build:json` first.
